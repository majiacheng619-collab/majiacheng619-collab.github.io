# 实现取舍

## 阶段 1

- 我把阶段 0 作为只读基线。阶段 1 起用同一套检查记录结果，并把两轮后仍有差距的项目留下可复现的说明。
- Pages 继续沿用 Python 模板和原有发布流程。日常检查在 `_site` 生成页面，`deploy.zip`、原始简历、影片母版和游戏的资源都作为现有输入保留。
- 发布简历使用 `resume-beb4a3432690.pdf`。旧指纹地址当前返回 404，暂无旧原件可列差异。联系信息在访客点击后显示。静态网页的点按显隐不等于访问授权，简历原件仍可通过直链访问。
- 主站页面有 robots 元标记，robots.txt 移除了站点地图并限制游戏路径和 PDF 抓取。游戏已有独立的缓存和双向链接，发布树保持逐字节一致。
- 原作品截图继续使用，设备外框改为本地 CSS。Diyor 相关字样只在既有清理规则中出现。已下架短片素材缺失，作品入口留在已核实可用的三个项目。
- 预加载的光学 WebGL 背景改成静态渐变。液态丝带、按压高光和用户主动播放的实时 3D 场景继续承担动态表现。压缩视频是浏览版本，原始视频作为单独的下载项。
- Lighthouse 的 Chromium 单进程环境有 `NO_SCREENSHOTS`，故 Speed Index 和总性能分缺失。模拟节流与 DevTools 节流均尝试过。模拟节流测得首页移动 LCP 约 1.9 秒、TBT 0 ms。后续继续使用同环境记录原始指标，并补充能够返回完整分数的环境。

阶段 1 的补测用多进程 Headless Chromium 获得移动性能 65、桌面 63。移动端最大一项约 6.7 秒的长任务未归属到页面资源。总分受本地浏览器执行环境影响。

## 阶段 2

- 我为控制中心和小程保留独立的访问路径。Spotlight 复用小程的搜索面板和已有内容，索引与排序引擎在用户打开面板后载入。
- 我以 `data/profile.json` 保存现有经历与指标。视角切换只改变顺序和强调。两个利润口径沿用已有区别。
- Quick Look 截取经核查的简历首张页面正文，裁掉含联系方式的首部。下载继续使用已确认的原件。
- 首页继续游戏只读取有已完成进度且结构有效的本机记录。读取失败时隐藏入口，实际游戏继续由原引擎恢复。
- 音乐每次导航后等用户操作再播放，控制中心可记住上次选择。归档影片和游戏发布树保持不变。
- 下拉搜索的感应区位于主屏标识。Sheet 只在拉手接受拖动。浏览器边缘返回、主体滚动和下拉刷新保留原有入口。
- 英文偏好已能切换控制中心标签。独立英文内容在阶段 4 完成。
- Lighthouse 移动端多进程初测 60，LCP 约 1.9 秒。首载字节低于上一阶段，无障碍与最佳实践同为 100。复测和未达 90 的原因见后续记录。

阶段 2 移动端复测仍为 60。最大的长任务未归属到具体页面资源，且单进程测量的 TBT 为 0 ms。移动与桌面总分尚未达标。首载字节、真实交互通过率和分项结果继续比对。

## 阶段 3

- 我把联系页二维码指向本站联系页。按下下载按钮后才生成 VCF，名片保持点击显示与复制。预览和二维码均由本地构建生成。
- 游戏入口直接打开现有游戏页。产品页的连贯转场和游戏返回链接覆盖来回导航。内嵌试玩为可选项，当前采用兼容性较高的独立游戏链接。
- 荣誉有一张可用的原始凭证。查看器支持缩放和拖动，具备多图时的切换路径。
- 实时场景构建产物增加镜头输入，影片母版与离线逐帧渲染源码保留。方向传感器仅在点击后申请；权限缺失时可拖动或用方向键。省流量、减弱动效与可识别的低电量状态使用海报。
- 我从同一内容源制作 12 张故事卡，按 5 秒切换。观看者可以暂停或手动切换，前后台切换时计时暂停。
- 游戏 7.0.0 更新展示取自本地发布的更新日志。新页面沿用已发布事实。

## 阶段 4

- 我为主站使用独立命名的内容版本缓存。在线 HTML 优先走网络，离线读取当前版本。确认更新后仅清理本项目旧缓存。PWA 首载延后注册，省流量时跳过，游戏、影片、简历与实时 3D 不进入主站预缓存。
- 英文页与中文经历使用同一 `data/profile.json`。校名的英文使用拼音及中文原名，保留可核对的经历、时间和指标。纯文字版保留静态阅读、简历和联系入口。
- 浅深主题复测修复了旧标题、冰之圣殿控件和纯文字链接的对比度。28 次 axe 自动扫描无确定违规。玻璃叠层和图片背景仍有 865 次节点组合需要人工复核，含浅深模式重复的节点。
- Lighthouse 最终首页移动首测 61、桌面 61。复测移动 61、桌面 62。移动 LCP 1.88–1.89 秒，桌面 0.50–0.52 秒。多进程测量的未归属长任务仍拉低性能总分，缺少可定位到源文件的证据。归档保留这一差距，未将 90 作为通过结论。
- 我把实际 WebKit/Chromium 模拟和真机兼容分开记录。现场方向传感器权限、触感、低电量系统行为与各内置浏览器的下载能力仍取决于设备。
